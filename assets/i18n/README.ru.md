## Быстрый старт (30 секунд)

Выберите **один путь для каждого агента**: если поставить два, каждый skill загрузится дважды.

1. **Codex**: обновляется сам при каждом запуске сессии.
   ```bash
   codex plugin marketplace add LilMGenius/paperthin && codex plugin add paperthin@paperthin
   ```
2. **Claude Code**:
   ```bash
   claude plugin marketplace add LilMGenius/paperthin && claude plugin install paperthin@paperthin
   ```
   Затем в Claude Code выполните `/plugin`, откройте **Marketplaces**, выберите `paperthin` и один раз включите **Enable auto-update**.
3. **Любой другой агент**: одна строка ставит skills и ежедневное обновление.
   ```bash
   npx skills@latest add LilMGenius/paperthin --global --agent '*' && node "$HOME/.agents/skills/re0-upgrade/scripts/schedule/schedule.mjs" install
   ```
4. **Пользуйтесь**: наберите `/paperthin`, а за ним свою мечту. Вот и всё. Хотите понять, как это устроено? Не волнуйтесь, есть `/re0-tutorial`.
5. **Оплата звёздами**: если пригодилось, плата одна [звезда на GitHub](https://github.com/LilMGenius/paperthin). Дёшево, знаю.

**Уже ставили раньше?** Запустите `/re0-upgrade` один раз в новой сессии.

**Не уверены?** Скажите агенту [`install https://github.com/LilMGenius/paperthin`](../../.agents/install-block.md#handed-only-this-repository). Веб-чату дайте [llms.txt](https://raw.githubusercontent.com/LilMGenius/paperthin/main/llms.txt).

<a id="the-problem"></a>
## Проблема

**Большинство агентских skills - это slop.**

Дайте агенту цель, и он начнет **добавлять**: больше файлов, больше опций, больше "полезного" boilerplate. Добавление выглядит как прогресс, и ничто не заставляет его вернуться и удалить лишнее.

> [!WARNING]
> Повторите это в проекте несколько раз, и получите знакомый AI-generated toolkit: почти дублирующиеся skills, мертвые настройки, markdown-файл, который трижды говорит одно и то же. Правдоподобно, занято, и тихо непригодно к поддержке.

Эти skills ставят на обратное: **каждый что-то убирает**, а что именно, сказано в [индексе](#the-index).

> [!TIP]
> Трудная часть - не добавлять features, а удерживаться. Pass, который не нашел, что улучшить, ничего не меняет. **Это restraint и есть продукт.**

<a id="the-proof"></a>
## Доказательство

**NVIDIA измерила: агент, который бросает длинную историю и работает по короткой заметке, сохраняет результат.**

| Что измерила NVIDIA | Длинный контекст | Короткая заметка |
|---|---|---|
| SWE-bench Verified, Claude Opus 4.5 | 70.0 | 70.2 |
| Наибольший контекст, нужный прогону | 200K токенов | 16K токенов |
| Пропускная способность открытых моделей, H100 | окно 256K | до 7x выше при 16K |

<sub>Belcak и др. (NVIDIA), [You don't need long context](https://arxiv.org/abs/2611.05306), arXiv 2611.05306, 2026-11-03. Первая и вторая строки взяты из таблицы 2: Opus 4.5 действует по одному шагу на основе заметки о состоянии. Третья строка взята из рисунка 1 (GLM 5.2 3,6x, Kimi K2.6 5,6x, Qwen 3 Coder Next 7x).</sub>

**Какой навык Paperthin берёт на себя каждый вывод:**

| Что нашла статья | Навыки, которые это делают |
|---|---|
| Долгой работе не нужен длинный контекст: когда разговор заполнен, пишут заметку и продолжают в новом | `re0-work` начинает с v0 заново, взяв только проверенные уроки, `re0-git` оставляет передачу дел в истории git для следующей сессии |
| Хорошая заметка держит задачу близко к исходным словам | `re0-loop` оставляет каждый открытый запрос в списке, когда сессия сжимается или начинается заново |
| Хорошая заметка хранит, что делается, зачем и что дальше | `re0-memo` превращает законченный цикл в ворота следующего, `nba` называет следующий шаг |
| Хорошая заметка хранит план, условия готовности и где что лежит | `re0-plan` открывает цикл файлами дизайна, порядка работ и доказательств, `re0-workflow` записывает порядок навыков |
| Одно действие за раз по заметке о состоянии сохраняет полный результат | `shower` отдаёт одну заметку читателю без предыстории и спрашивает, понятна ли она сама по себе |
| Меньшее окно обслуживается до 7x быстрее | `elon` убирает то, что держится лишь по привычке, `debloat` оставляет то, что несёт нагрузку, `re0` переписывает вместо новых заплаток |
