# Failure taxonomies

Step 7 of `re0-memo` holds the memo's lesson classes up against the failure breakdowns a field already publishes, so a class the memo never named is found from a source rather than from memory, and a class only the memo names is marked as the cycle's own reading. The procedure is distilled from `domain-gaps`, a skill in the same author's LilMSkills collection that checks any remembered list against a field's authorities: its source classes, its one-list-per-source rule, its alias line and its verdicts are kept, and its comparison script is replaced by one hand-written table, since a memo holds a handful of classes and aligning them is judgment.

## Seed

The seed is the memo's classes at the rung step 5 left them, one line each, written before any source is read. Do not tidy it first: the seed records what the cycle saw.

## Sources

Name the breakdowns that would settle which failures the field knows, in this trust order, and save at least one:

| Class | What it is | Example for a lesson about handing work to another actor |
| --- | --- | --- |
| `standard` | a standards body's document or a canonical textbook | a security standard's access-control requirements; the principle of least privilege |
| `survey` | an academic survey or published taxonomy | a published classification of human error or of organizational accidents |
| `practitioner` | a postmortem collection or a breakdown by someone who ran the work | incident postmortems, a responsibility matrix such as RACI, a military doctrine of delegated command |
| `changelog` | release notes of the tool or platform the work runs on | the platform's notes on what a token or role may and may not do |
| `community` | the field's own forum, read as dated snapshots | recurring questions about what an automated account cannot do |

Each source is saved beside the memo as a plain-text file headed with its URL, the time it was fetched and the status the server answered, so a later reader can open what the ruling cites. A source that cannot be fetched is replaced by another of its class or named in the memo as missing; a remembered taxonomy is a lead to fetch, never a source.

## Compare

1. Draw one list per saved source: the source's own failure classes in its own terms and nesting, nothing it does not say.
2. Write one alias line for each class two lists name differently, `Canonical = other name`, merging only names that mean the same thing at the same level.
3. Write the coverage table, one row per class, one column per source and one for the memo, with `x` where a list names it.
4. Rule on each row the memo lacks: `add` (a new lesson class, or a sibling for step 6), `merge` (it belongs inside a memo class, which widens that class's wording) or `drop` (outside this cycle's work), each with a `[source]` citation of a saved source that names it. Weigh a row by its class before its count: one a standard names is added unless the memo's scope excludes it on purpose; two lists by one author are one voice.
5. Rule on each memo class no source names: `keep`, saying what the cycle saw that no source writes down, so it stays marked as the cycle's own reading; or `noise`, when it restates another class or names nothing.

## Write

The table and the rulings go into the memo's field check section, each ruling also noted under the lesson it touches. A merged class widens that lesson's wording and runs back through steps 5 and 6. An added class becomes a lesson only when the cycle's records or the sibling search of step 6 hold a case of it, and then runs through steps 5 and 6 before any prescription is drafted for it; until then it stays in that section as a field candidate with its source, since every lesson traces to evidence from the cycle.
