# VibeGhost

### The Ghost for vibe coders: Git-backed load/save for AI coding environments (`.agenv`)

Apply a known-good setup across Windows, macOS, and Linux. VibeGhost restores the tools, settings, services, launchers, and agent skills that make up an AI coding environment.

## Install

```bash
npx -y skills@latest add LilMGenius/vibeghost --global --agent '*' --skill '*' -y
```

Call `$load` to apply an environment or `$save` to capture intentional changes.

Call `$init` to install Desktop launchers, check installed tools against publisher releases, update managed packages, and repair startup paths. Repository-owned skills can share their source files with multiple agent installations. See [maintenance and source links](./references/contract.md#maintenance-and-source-links) for commands and platform coverage.

## Personal snapshot

Defaults live in [`manifest.json > snapshotDefaults`](./manifest.json). The default private repository is `.agenv`, with `dotagenv` as the provider fallback, and the local checkout is `~/.agenv`. Secrets stay excluded unless `$save` receives explicit confirmation.

Both skills accept `repo`, `path`, `visibility`, `message`, and `include-secrets` parameters. `$save` can initialize Git, create the private repository, commit, and push; `$load` clones the selected repository before applying it.

## Verify

```text
Windows:     pwsh -NoProfile -File .\scripts\bootstrap.ps1 -DryRun
macOS/Linux: ./scripts/bootstrap.sh -DryRun
```

Review the plan, remove `-DryRun`, then run:

```text
pwsh -NoProfile -File ./scripts/verify.ps1 -Mode Live
```

The bootstrap puts every launcher declared in `manifest.json > desktopLaunchers` on the Desktop, picking the file for the running platform; on Windows each one is a hardlink to the checkout file, so it stays a real `.cmd` that follows the checkout. The CPA launcher resolves `CLI_PROXY_API_HOME` at launch time. See [`references/contract.md`](./references/contract.md) for restore, snapshot, and failure gates.

When the machine goes silent while the audio stack still reports healthy, run `audio-reset.cmd` on Windows or `audio-reset.command` on macOS from the Desktop. Both run `./scripts/audio-reset.ps1`, which recycles the audio engine for that platform and reports whether it actually restarted.

For a Windows-hosted provider used from WSL, follow the [runtime boundary preflight](./references/contract.md#runtime-boundary-preflight) before starting an isolated review. WSL host networking is a manual prerequisite and is not restored by bootstrap.
